# Практическая часть Assignment 3

Это выполненный первый эксперимент по прогнозу результативности футболистов после трансфера. Данные реальные; результаты находятся в outputs. Отчёт на английском соответствует языку Assignments 1 и 2.

## Как повторить запуск

Нужен Python 3.12. Из папки practical:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe run_pipeline.py
```

Код использует сохранённые CSV в data и перезаписывает вычисленные файлы в outputs. Сетевое соединение для повторного анализа не нужно после установки библиотек. Исходные CSV не изменяются. Параметры и версии зафиксированы; время выполнения может отличаться.

## Файлы

- run_pipeline.py — весь выполняемый код, включая проверки хронологии, построение выборки, модели, метрики и анализ ошибок.
- data — четыре исходных сжатых CSV, загруженные 12 октября 2026 года из открытого проекта dcaribou/transfermarkt-datasets.
- outputs/source_manifest.json — URL источников, дата получения и SHA-256 каждого исходного файла.
- outputs/transfer_cohort.csv — 781 трансфер с признаками, целевым значением и временным разбиением.
- outputs/results.json — полные результаты и настройки.
- outputs/test_predictions.csv — фактические значения, прогнозы обеих моделей и ошибки для 242 тестовых трансферов.
- outputs/permutation_importance.csv — важность признаков на тестовой выборке.
- outputs/largest_errors.csv — примеры максимальных ошибок.
- outputs/formation_rf.joblib — обученная модель с препроцессингом.
- outputs/run_log.txt — журнал фактического запуска.

Источник: https://github.com/dcaribou/transfermarkt-datasets. Данные зафиксированы как snapshot. Не предполагается, что они автоматически обновляются. Исходные файлы содержат дополнительные публичные поля; код читает только поля, необходимые для исследования.

## Что важно понимать перед защитой

1. Метод — ретроспективный сравнительный ML-эксперимент. Две модели прогнозируют одно и то же на одинаковых строках; отличается набор признаков.
2. Единица анализа — один трансфер одного игрока. Сохранён первый подходящий трансфер каждого игрока, поэтому личности не пересекаются между train, validation и test.
3. Целевая переменная — 90 × (голы + голевые передачи) / минуты в первом сезоне нового клуба. Это атакующая результативность, а не вся полезность футболиста.
4. Признаки игрока и схемы нового клуба берутся из предыдущего сезона. Данные будущего сезона используются только как target. Проверки дат находятся в коде.
5. Train: 2018–2021, validation: 2022, test: 2023–2024. Модели обучены на 405 строках, валидируются на 134 и тестируются на 242.
6. После исправления названий схем добавление контекста не улучшило основной результат. H1 и H2 не подтверждены этим запуском. Нельзя говорить, что тактика вообще бесполезна: измеряется только история номинальных схем.
7. Для Objective 4 модель переобучается без трансферов, затрагивающих выбранную лигу с любой стороны. Далее тестируются поздние трансферы в неё из других лиг.
8. Permutation importance измеряет изменение ошибки при перемешивании признака. Это зависимость прогноза от признака, не причинное влияние тактики.
9. Исправленный сбой — точные сравнения строк пропускали варианты «4-3-3 Attacking» и «4-4-2 double 6». Теперь извлекается числовая схема. Отрицательный результат не скрыт.
10. Ограничения: нет прессинга и владения, позиция игрока взята из позднего профиля, фильтр по минутам исключает часть неудачных трансферов, bootstrap пока не учитывает кластеризацию по клубам.

## Добавленные схемы и интеграция

В diagrams находятся схемы System Flow, Entity Relationships and Data Flow, End-to-End System Integration и ML Preprocessing Pipeline. Они описывают фактическую архитектуру CSV + Python + сохранённые модели, без заявления о несуществующем сервере или базе данных.

